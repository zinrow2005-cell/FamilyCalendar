# 家日曆 V2.3 — 家人全自動同步

這個版本使用原有的 **Google Sheets ＋ Apps Script** 後端及家庭共用金鑰，前端取消人工「同步衝突」處理介面，改為自動重試、逐筆合併、持續同步。

## 與 V2.2.1 不同之處

- 輸入一次 `/exec` Apps Script 網址和 64 碼家庭密鑰，成功連接後會保存在目前裝置，之後開啟自動嘗試連線。
- 有網路且 APP 正在開啟時，本機新增／修改／刪除事項約 1 秒後開始自動上傳；其他裝置每 20 秒檢查雲端更新，重新切回網頁或網路恢復時也會立即檢查。
- 無網路／上傳未成功時資料先保留本機；重新連上網路後自動重試。
- 兩台裝置新增不同事項會保留兩筆；同一事項若修改不同欄位會合併；同一欄位互相修改時以最後成功寫入雲端的版本為準。
- Google Apps Script 後端**仍保留版本鎖（CAS）**，版本不同時由前端在背景重新讀取、合併並重試，防止整份資料被直接互相覆蓋。不再要求使用者手動選擇本機或雲端版本。
- 首次接入已有雲端資料時，會保留其他裝置的事項，並將此裝置本機已有事項依 ID 併入。

## 請注意：同步不是即時推播

Google Apps Script＋Google Sheets 不是 WebSocket 即時資料庫。其他裝置只有在打開 APP（或回到 APP）時才能下載更新，前景執行時約每 20 秒輪詢一次。APP 關閉或被作業系統暫停時不會繼續背景同步。Google 服務網路、速度或使用額度也可能影響實際延遲。

## 升級步驟

1. **先在電腦及手機各自匯出 JSON 備份**，尤其是手機之前有顯示「同步衝突」或尚未同步資料時。這很重要，因為 V2.3 不會再詢問你要保留哪個版本。
2. 解壓 ZIP，把 `index.html`、`app.js`、`styles.css`、`sw.js`、`manifest.webmanifest` 和整個 `icons`、`illustrations` 資料夾覆蓋 GitHub Pages 專案的既有檔案。
3. 開啟 APP，檢查頁首是否顯示 `V2.3`；若顯示舊版，重新整理頁面，必要時移除舊 PWA 捷徑並重新安裝。
4. 若前一版已儲存 Apps Script 網址與密鑰，通常會沿用；否則到「Google Sheets 家人同步」輸入一次即可。
5. 在手機建立測試事項，等待狀態顯示「Sheets 自動同步」；再到電腦切回 APP（或等待約 20 秒），確認測試事項出現；接著反方向測試。

## 後端是否需要更新？

不需要。ZIP 內 `AppsScript/Code.gs` 與 `Bridge.html` 沿用 V2.2.1。已經可以連線的 Google 試算表、家庭密鑰與 Apps Script `/exec` 網址都可繼續使用。

## 資料安全與同步規則

- 不同事項：依唯一 ID 合併，避免一人新增事項時清掉其他人的新事項。
- 同一事項不同欄位：保留各欄位最後提交的修改，例如電腦改地點、手機改時間會合在同一筆。
- 同一欄位：**最後成功提交的版本覆蓋先前版本**，不跳出衝突視窗；因此可能覆蓋他人剛剛的更改，建議對重要資料保留定期備份。
- 同一筆被刪除與編輯：以後成功提交的操作為準；若編輯較晚提交，事項可能被恢復。
- 修改或刪除大量事項前，仍建議先匯出完整 JSON 備份。
- 共用金鑰是家庭帳號的共用密碼：不要貼在公開 GitHub 專案或傳給陌生人。共用裝置上的密鑰會存在該瀏覽器本機儲存空間中。

## 檢查狀態

- `Sheets 自動同步`：此裝置目前已連線，沒有已知待同步錯誤。
- `自動上傳中…`：資料正在送往 Google Sheets 並確認寫入結果。
- `⚠ 待上傳（自動重試）`：暫時不能確認上傳，資料仍在本機，網路或服務恢復後會重試。
- `⚠ 等待自動重連`：尚未連上試算表，會在開啟頁面的狀態下自動重新嘗試。

## 測試範圍

已使用 Chromium 模擬的三個裝置與共用後端進行 10 項資料情境測試；桌機／平板／390px 手機／360px 手機的同步設定視窗基本操作測試亦通過。**尚未連接你的真實 Google Sheets，也尚未在 iPhone Safari 實機測試。**

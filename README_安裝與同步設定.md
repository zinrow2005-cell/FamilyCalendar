# 家日曆 V1.9：Google Sheets + Apps Script 家人同步

本版是從 **V1.6 重複事項期限與彈性修改版** 改造，保留原來的行程、每位成員的代表色與照片、個人常用事項、柔和調色盤、醫院不規則批次排班，以及重複事項只改一次／往後／全系列修改。

## 一、更新 GitHub Pages

1. **請先在上一版下載 JSON 完整備份**。尤其是原本已使用 Firebase 共用的人，務必從已成功載入雲端行程的上一版匯出，而不是只備份舊本機紀錄。
2. 上傳 ZIP 最外層的 `index.html`、`app.js`、`styles.css`、`sw.js`、`manifest.webmanifest` 和 `icons/` 到原本 GitHub Pages 專案。**不要把 `AppsScript/` 裡的 Code.gs 當成 GitHub 前端程式執行**；該資料夾需要貼入 Google Apps Script。
3. 重新整理或關閉後重新開啟 PWA，確認左上標示 **V1.9**。如果載入舊版，可從手機主畫面重新開啟，或清理此網站的舊快取（清除網站資料前先備份）。
4. `familycolor_v1_local` 的儲存鍵維持不變，通常會保留原本同網址的本機紀錄；但瀏覽器或網址不同、或舊版原本只存在 Firebase 雲端時，仍要靠 JSON 匯入轉移。

## 二、建立自己的 Google Sheets 資料庫

1. 用 Google 帳號建立一份新的**私有** Google 試算表，例如 `家日曆_家庭共用資料庫`。**不要**設為「知道連結的任何人可編輯」，建議只讓你本人擁有編輯權。
2. 開啟「擴充功能 → Apps Script」。把 `AppsScript/Code.gs` 的**完整**程式碼貼進預設的 `Code.gs`，取代原內容。
3. 點左側 `＋` → `HTML`，名稱填 `Bridge`（不含 `.html`），把 `AppsScript/Bridge.html` 完整貼上並儲存。名稱務必相同。
4. 回到**試算表網頁並重新整理**。上方會出現 **「家日曆設定」** 選單。點「首次初始化／檢查工作表」，依畫面要求授權。系統會建立 `設定`、`家庭成員`、`日曆事項`、`常用事項` 四個工作表。
5. 首次初始化會跳出一組 **64 碼家庭共用密鑰**，請儲存在安全的地方。這不是 Google 密碼，**不要貼到 GitHub、公開訊息或網址內**。已初始化後再次執行，不會重複顯示密鑰；忘記可使用選單「更換家庭共用密鑰」。
6. 再回到 Apps Script 編輯器，點右上「部署 → 新增部署作業 → 類型：網頁應用程式」。設定：
   - **執行身分：我**（即試算表擁有者）
   - **誰可以存取：任何人**（如果你的帳號管理政策不允許，這種密鑰共用方案便無法直接使用）
7. 完成部署後，複製結尾是 `/exec` 的網頁應用程式網址。請使用 `/exec`，**不要**使用 `/dev`。

> 為何部署成「任何人」？因為 GitHub Pages 的靜態 PWA 不是執行在 Apps Script 的 Google 帳號環境裡。後端所有家庭讀寫都會檢查密鑰；不持有密鑰就不能讀取或修改內容。它是**家庭共用密鑰模式，不是逐人 Google 帳號權限模式**。

## 三、在家日曆連線

1. 用 GitHub Pages 的正式 HTTPS 網址開啟家日曆，按畫面右上「本機日曆」。
2. 將 Apps Script `/exec` 網址貼入第一個欄位。
3. 將首次初始化獲得的 **64 碼家庭共用密鑰** 貼入第二個欄位，按「連接並檢查」。
4. 若首次連線時本機也已有事項，會要求選擇：
   - **使用試算表的資料**：以共用試算表目前內容作為此裝置的行程。
   - **將本機資料合併上傳**：將這台裝置已有的行程上傳，遇到相同 ID 時以本機內容為主；建議先備份。
5. 連線完成後，上方狀態顯示 `Sheets 已同步`。在網路正常時，新增／編輯／刪除通常會在約 1 秒後開始上傳。保持開啟時，系統約每 60 秒檢查其他家人的修改；重新開啟頁面也會檢查。

## 四、其他家人連線

- 傳送**家日曆的 GitHub Pages 網址**給家人。也可在家日曆「Google Sheets 家人同步」畫面選「複製家人連線網址」，它只帶入 Apps Script 網址，**不會包含密鑰**。
- 透過**另一個私密管道**告知家人共用密鑰；他們在自己的手機／電腦首次輸入一次即可。這不是 Google 帳號 OAuth 登入，不會辨識誰使用了哪個 Gmail。
- 密鑰等同整個家庭的讀寫權限；若某人不再需要權限，需在試算表的「家日曆設定 → 更換家庭共用密鑰」，然後讓仍受信任的家人重新輸入新密鑰。

## 五、同步、離線和衝突

- 編輯時**先存本機**，網路暫時失敗也不會把畫面上的編輯直接丟棄。請留意 `⚠ 待同步`，恢復網路後手動按「立即同步」或重新開啟頁面。
- Apps Script 伺服器使用 `LockService` 與**修訂版號**檢查，防止兩台裝置盲目互相覆蓋。
- 不同事項同時修改：可合併；**同一筆事項**同時被改：會標示 `⚠ 同步衝突` 並暫停上傳，需選擇「改用雲端」或確認「保留本機修改」。請先下載 JSON 備份再處理衝突。
- 大量舊行程匯入採分批同步（每批最多 250 個資料項目），請勿在上傳尚未完成前立即關閉頁面。
- 成員照片會壓縮後以資料內容保存在 Google Sheets，每張縮圖小於約 24,000 字元；原始大照片不會直接上傳。
- 若瀏覽器的第三方網站限制、Apps Script 部署設定或 Google 管理政策阻擋 iframe / `google.script.run`，可能無法建立橋接；此時本機日曆仍能使用。先確認 `/exec` 部署及權限，改用正式 HTTPS 網址測試。

## 六、資料表與重要限制

| 試算表工作表 | 儲存內容 |
|---|---|
| `設定` | 家庭名稱、同步修訂版號及更新時間 |
| `家庭成員` | ID、姓名、圖示、專屬色及壓縮照片 |
| `日曆事項` | 單次行程、批次值班、重複有效期間、例外日期、顏色、時間、成員 |
| `常用事項` | 每個家庭成員的快捷事項範本 |

資料列採 `ID` + `JSON資料` 兩欄存放，以保留原本系統的完整結構。**試算表內不應直接隨意修改 JSON 字串**，建議透過家日曆操作。

**尚未實際連接你的個人 Google 試算表測試**（你尚未提供部署網址）。此版本已在 Chromium 模擬前端與試算表後端邏輯進行測試，但真正的 Google Apps Script 授權、部署、iframe 及各台 iOS Safari 仍需依照上述步驟實測。亦請留意 Google Apps Script 的執行與服務配額。

# 家日曆 V1.9.1 — 手機 Google Sheets 同步修正版

## 為什麼電腦可用、手機連線失敗？

V1.9 將 Apps Script 網頁應用程式放在 GitHub Pages 的隱藏 `iframe` 內，再用 `postMessage` 與 `google.script.run` 通訊。這條路徑在 iOS Safari、部分 Chrome/Android 的第三方網站或跨網站防護環境可能被阻擋；Google 也曾有 iframe 嵌入被瀏覽器攔阻的問題。這是**可能原因**，並未直接檢測到你的手機，所以不能斷言一定是它。

V1.9.1 改為**不需 iframe 的資料傳輸**：以短時間有效的 HMAC 簽章讀取 Google Sheets（前端使用簽名 JSONP GET），寫入則以 `no-cors` 表單 POST 傳送後再讀回版本與資料核對，才能顯示已同步。真正的家庭共用密鑰不放入網址。保留既有 Sheets 工作表、資料欄位、修訂版與衝突保護；舊版電腦端的 `Bridge.html` 介面在 Apps Script 仍保留，因此可以逐台升級。

> 注意：JSONP 本身並不是理想的私密資料 API，Google 官方也提醒 JSONP 讀取機制的安全風險。本修正版以短時效、隨機 nonce、綁定回呼名稱的 HMAC 簽章降低風險，但**不等於完整的使用者身分驗證或專業安全稽核**。涉及敏感醫療資訊、孩子詳細行蹤等資料時，請評估改成使用具正式登入與 CORS 支援的後端服務。

## 升級步驟（順序重要）

### 1. 先備份

在**仍可成功同步的電腦**開啟 V1.9，確定顯示 `Sheets 已同步`，匯出「完整 JSON 備份」。如果手機上已有未同步的行程，也請先用手機另外匯出一份，以免首次連線選錯資料來源。

### 2. 更新 Apps Script（必做）

1. 打開原本的 Google Sheets →「擴充功能」→「Apps Script」。
2. 將 ZIP 裡 `AppsScript/Code.gs` 的**完整內容**取代 Apps Script 裡現有 `Code.gs`，儲存。`Bridge.html` 可保留原本的，也可以換成新版隨附的相同檔案；**不要刪除它**，因為尚未升級的電腦需要它。
3. 按「部署」→「管理部署作業」，選擇**現有的網頁應用程式部署**→鉛筆「編輯」→「版本：新增版本」→「部署」。注意不要只按「儲存」而不更新部署版本，也不必重新建立新試算表或換密鑰。
4. 確認網頁應用程式設定仍為「執行身分：我」「誰可以存取：任何人」。
5. **原本的 `/exec` 網址不需要更換**（前提是編輯既有部署而非另建部署）。

### 3. 更新 GitHub Pages

把 ZIP 根目錄的 `index.html`、`app.js`、`styles.css`、`sw.js`、`manifest.webmanifest`、`icons/` 上傳原本 GitHub Pages 專案的相同位置，覆蓋舊版。`AppsScript/` 是貼到 Apps Script 的後端程式，不需要放到 GitHub 公開倉庫。

重新整理後確認頁首版本為 **V1.9.1**。如果主畫面安裝的 PWA 還顯示 V1.9，先用手機 Safari/Chrome 的一般瀏覽器分頁打開正式 GitHub Pages 網址，確認版本後再測試。清除網站資料會一併清掉本機行程與同步密鑰，未備份前勿清除。

### 4. 手機連線

1. 先用手機 Safari / Chrome **一般分頁**，開啟正式 GitHub Pages 的 HTTPS 網址（避免 LINE、Messenger 或其他 APP 內建瀏覽器）。
2. 確認頁首為 `V1.9.1`，開啟右上「Google Sheets 家人同步」。
3. 貼上原本同一個 Apps Script `/exec` 網址，以及同一組 64 碼家庭密鑰。
4. 按「連接並檢查」。若出現「首次連線，請選擇資料來源」，且手機沒有獨有的未同步行程，請選 **使用試算表的資料**；如果手機有獨有行程，先完整備份後再決定是否合併。
5. 新增一筆不含敏感資料的測試事項，確認頂端顯示 `Sheets 已同步`；到電腦查看同一筆行程。反向用電腦新增事項，手機點「立即同步」確認能收到。

## 若還是失敗，看具體錯誤

- **「無法載入 Google Apps Script 回應」／「未收到回應」**：可能 Apps Script 沒部署**新版本**、網址不是真正的 `/exec`、Google 帳號或管理政策限制「任何人」存取、手機網路防護攔阻；請先在一般 Safari/Chrome 測試。
- **「家庭共用密鑰或簽章不正確」**：檢查密鑰是不是從原本資料庫產生的，且未多複製空格、換行。
- **「手機時間與伺服器相差過大」**：請開啟裝置的日期與時間自動設定後再測試。
- **「尚未確認寫入完成」**：手機資料已保留本機；進 Apps Script「執行紀錄」查看 `doPost` 是否執行與錯誤。可能是 Apps Script 版本未更新、權限或網路寫入問題。**不要重複匯入或清除資料**。
- **頁首仍是 V1.9**：GitHub Pages / PWA 舊快取尚未更新，不要只更換 Apps Script。

**切記：不要將 64 碼密鑰傳到公開 GitHub、截圖或公開討論中。** 若需要尋求排錯協助，提供錯誤文字與模糊化後的 `/exec` 網址即可，勿傳密鑰。

## 測試範圍與限制

完成了 JavaScript 語法、簽章一致性（實際 SHA-256 / HMAC）、篡改簽章拒絕、讀取／POST 寫入／讀回確認與過期版本衝突等本機模擬後端測試；另外以 Chromium 驗證桌機、平板、390px 與 360px 手機尺寸的日曆與連線表單。未連上使用者自己的 Google Apps Script 部署，未做真正 iOS Safari / Android 實機或 Google 伺服器的端到端驗證。若是 Google 帳戶管理政策禁止公開網頁應用程式，此方案仍可能無法使用。
